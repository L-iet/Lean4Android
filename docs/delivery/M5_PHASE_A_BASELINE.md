## Licenses

Mathlib and seven dependencies carry Apache-2.0 license texts. `Cli` carries MIT. The inventory records the exact nine license payload hashes. A pack producer must copy and declare these payloads rather than relying on repository URLs at install time.

## Capacity implication

The unfiltered expanded tree is about 6.96 GB in addition to the existing roughly 2.19 GB Core/Std Android runtime. This is not steady-state pack guidance: it includes known producer-only material, while staging and rollback could require multiple pack-sized trees. M5 must establish the required facet set before setting minimum free-space policy or claiming store feasibility.

## Next gate

Phase B starts from this complete cache and must run the representative and broad-import conformance corpus through host and Android `lake lean`, `lake build`, `lake serve`, editor intelligence, tactics, and supported interpretation. ## Phase B compatibility finding

The completeness-first API-33 probe proved that the official Linux cache cannot be the shipped artifact source. Lake resolved the all-local Mathlib plus eight-dependency graph without Git and reached target 2,997 of 2,998, but Android Lean rejected the first Mathlib `.olean` with `incompatible header`.

The byte evidence explains the incompatibility. Official Mathlib and official Lean v4.32.1 artifacts have an olean header naming `4.32.1` and commit `f054605…`. The current Android Core/Std artifacts were generated by the checked-in cross-build's previous-stage compiler and name `4.32.0-pre` with no release commit in that header, even though the resulting Android executable reports Lean 4.32.1 at commit `f054605…`. The Android runtime accepts its own `4.32.0-pre` Core/Std artifacts and rejects the official `4.32.1` cache.

Therefore M5 needs a clean Android-artifact target tree built with the same pinned previous-stage compiler that produced the accepted Android Core/Std files. The official cache remains useful for source/provenance, facet/size inventory, and host conformance, but its compiled facets must not be relabeled or header-patched. The pack identity remains bound to `lean-4.32.1-android1`, not merely the upstream Lean version.

A targeted attempt confirmed that the bootstrap compiler itself is not sufficient for Mathlib. It generated matching `4.32.0-pre` headers for a small probe and dozens of dependencies, then reproducibly aborted in Batteries and Qq with an IR-interpreter `unreachable` assertion. The compatibility problem must therefore be fixed at the toolchain producer boundary: build the true host stage1 compiler, use it to regenerate a new Android Core/Std toolchain revision, and build Mathlib with that same release compiler/artifact ABI. The known-good `android1` distribution remains preserved until the replacement passes its full existing conformance matrix.

That producer correction is now host-proven. A crash-interrupted host stage1 build was recovered incrementally and completed at exact Lean commit `f054605aea4b840552cca2e725580bffd1e1b704`; its Lean binary reports 4.32.1 Release and its matching Lake reports Lean 4.32.1. The stage1 compiler emitted a probe olean with exact `4.32.1` plus the full commit header.

A genuinely clean, exact-pinned Mathlib/dependency tree then built `Mathlib.Data.Nat.Prime.Basic` locally with `--no-cache` in 605 jobs. This crossed both bootstrap failure sites (`Batteries.Tactic.Lint.Simp` and `Qq.Macro`) and completed without dependency updates, cache downloads, or network resolution. The resulting target olean is 54,168 bytes, SHA-256 `c900db3d2609608d2cfa8519d6eccaa9206b15b7edb26006fc466f5fd830d330`, and carries exact release header `4.32.1` plus commit `f054605aea4b840552cca2e725580bffd1e1b704`. Its `.ilean`, `.olean.private`, `.olean.server`, and `.ir` companions were also produced.

The isolated Android Core/Std release-ABI cross-build and distribution are now host-complete as `lean-4.32.1-android2`. All 2,433 main build-tree oleans carry exact release version/commit headers, complete object/archive/ELF/dependency audits passed, and the final distribution manifest declares 14,898 payload files / 3,667,196,078 bytes with SHA-256 `9b93929b9ac06891ac943eb1373b87d98fdfb687e8c228979e4d8734fc8cb544`. The accepted Android1 distribution and app constants remain unchanged. The next compatibility gate is an isolated Android2 APK followed by the full existing Core/Std physical-device conformance matrix; only after that evidence may Android2 be promoted or used as the required identity for the complete release-ABI Mathlib pack.
